## 1. 需求概述

在 Snow Grass 后端增加类似 Codex 的 Skill 脚本能力：选中 Skill 后，模型可按 `SKILL.md` 指令请求执行该 Skill 已发布包内的 Python 脚本，并基于脚本结果继续回答。

## 2. 范围

**In scope（本次做）**：

- 为 OpenAI-compatible Chat Completions 增加函数调用消息和流式 tool call 解析。
- 在 Agent Runner 中增加多步“模型请求脚本 → 后端执行 → 结果回传模型”的循环。
- 仅暴露当前激活 Skill 包内 `scripts/*.py`，使用参数数组执行，不解析 Shell 命令字符串。
- 使用临时目录物化 Skill 包，校验相对路径，限制参数、超时和输出大小，并输出 SSE 执行步骤事件。
- 更新 Skill 校验提示、运行配置、README 和自动化测试。
- 为现有天气 Skill 增加实际 Python 查询脚本并发布新版本，使天气问题可走脚本执行链路。

**Out of scope（本次不做）**：

- 不执行 JavaScript、Java、二进制文件或任意 Shell。
- 不提供容器级或虚拟机级强隔离；脚本仅适用于经过管理端审核并发布的可信 Skill。
- 不改 Sedum 页面，不新增 API 或埋点，不提供人工逐次审批 UI。

## 3. 功能要点

| # | 功能点 | 描述 | 优先级 |
|---|--------|------|--------|
| 1 | 脚本发现 | 从当前激活 Skill 的不可变 Release 中发现 `scripts/*.py` | P0 |
| 2 | 模型函数调用 | 以 `run_skill_script` 函数向支持 OpenAI-compatible tool calls 的模型声明脚本及参数 | P0 |
| 3 | 受控执行 | 直接调用当前 Python 解释器，禁止 Shell，校验路径、参数、超时及输出 | P0 |
| 4 | Agent 循环 | 将执行结果作为 tool message 返回模型，直到产生最终文本或达到 `max_steps` | P0 |
| 5 | 可观察性 | SSE 输出脚本执行开始、完成或失败事件，最终 Token 汇总覆盖所有模型轮次 | P1 |
| 6 | 天气验证 | 天气 Skill 通过包内脚本查询 wttr.in，并由 DeepSeek 整理返回 | P1 |

## 8. 技术实施方案

### 8.1 架构决策

| 决策 | 选择 | 原因 | 放弃的方案 |
|------|------|------|-----------|
| 调用协议 | OpenAI-compatible function calling | DeepSeek/GLM 适配层可复用，参数结构明确 | 解析模型输出中的自定义 Markdown/JSON，容易泄漏控制文本且不稳定 |
| 执行入口 | 单一 `run_skill_script` 动态工具 | 与 Skill 包天然关联，不需要为每个脚本注册后端代码 | 给每个天气/业务场景硬编码 Tool，可扩展性差 |
| 进程启动 | `create_subprocess_exec` + 参数数组 | 不经过 Shell，避免命令拼接注入 | `shell=True` 或直接执行 SKILL.md 中命令，风险过高 |
| 文件来源 | 当前激活 Release 的 `package_files` | Release 不可变，可追溯且不会读取未发布草稿 | 直接执行编辑中的草稿，行为不可审计 |
| 执行边界 | 可信已发布 Skill + 临时目录/超时/输出限制 | 当前无容器运行时，可先提供明确的本地可信脚本模型 | 宣称子进程即强沙箱，不符合实际安全能力 |

### 8.2 数据流

```text
src/snow_grass/api/router.py#stream_message
→ src/snow_grass/agent/runner.py#AgentRunner.stream
→ src/snow_grass/providers/openai_compatible.py#stream_chat
→ model tool_call(run_skill_script)
→ src/snow_grass/skills/executor.py#SkillScriptExecutor.execute
→ tool message
→ model final answer
→ SSE message.completed
```

### 8.3 改动详情

#### `src/snow_grass/providers/base.py`（修改）

- 定义工具 JSON Schema、完整 tool call 及流式增量模型。
- `ChatMessage` 支持 assistant tool calls 与 tool result 消息。
- `ModelProvider.stream_chat` 接受可选工具列表。

#### `src/snow_grass/providers/openai_compatible.py`（修改）

- 将工具列表传入 Chat Completions。
- 按 index 聚合前将 delta 中 id、函数名和参数片段透传给 Runner。

#### `src/snow_grass/agent/runner.py`（修改）

- 仅当 Skill 包存在可执行 Python 脚本且配置已开启时暴露工具。
- 每轮收集文本、tool calls 和 usage；有 tool call 时执行并追加 tool message，无 tool call 时结束。
- 使用 `manifest.limits.max_steps` 限制模型与工具循环。

#### `src/snow_grass/skills/executor.py`（新增）

- 校验脚本必须是当前 Skill 的 `scripts/*.py`。
- 物化安全相对路径到临时目录。
- 通过当前 Python 解释器直接启动脚本，限制参数数量/长度、执行时间及 stdout/stderr 大小。
- 返回结构化 JSON 结果，错误不暴露服务端敏感路径。

#### `src/snow_grass/skills/validation.py`（修改）

- 拒绝 `scripts/` 下非 `.py` 文件，避免产生“已打包但无法执行”的误解。
- 提示脚本以服务进程账号运行，只应发布可信代码。

### 8.4 状态管理

无新增持久化表。一次 Run 的 tool calls 和脚本结果只存在于 Agent Runner 内存中；最终对话仍只保存用户和助手消息。

### 8.5 异常处理

| 场景 | 处理方式 | 涉及文件 |
|------|---------|---------|
| 模型请求不存在的脚本 | 返回结构化 tool error，由模型解释，不启动进程 | `skills/executor.py` |
| 参数或路径不安全 | 拒绝执行并产生失败 step | `skills/executor.py`、`agent/runner.py` |
| 脚本超时 | 终止子进程，返回 timeout error | `skills/executor.py` |
| 输出过大 | 截断并标记 truncated | `skills/executor.py` |
| 模型循环超过上限 | Run 失败并返回稳定错误码 | `agent/runner.py` |
| Provider 不支持 tool calls | Provider 返回配置错误；普通无脚本 Skill 不受影响 | `providers/openai_compatible.py`、`agent/runner.py` |

## 9. 验收标准（AC）

### AC1：执行已发布脚本

- **Given**：当前激活 Skill 包含 `scripts/example.py`，脚本执行已开启，模型请求该脚本。
- **When**：用户发送匹配该 Skill 的消息。
- **Then**：后端执行脚本、将输出返回模型，并产生最终 assistant 消息和脚本 step 事件。

### AC2：阻止越界执行

- **Given**：模型请求 `../x.py`、绝对路径或包内不存在的脚本。
- **When**：Runner 处理 tool call。
- **Then**：不创建对应进程，返回安全错误，且 Run 不泄露服务器绝对路径。

### AC3：限制资源

- **Given**：Skill 脚本执行时间或输出超过配置上限。
- **When**：执行器运行脚本。
- **Then**：超时进程被终止或输出被截断，Agent Run 可控结束。

### AC4：天气 Skill 实际调用

- **Given**：天气 Skill 新版本已激活且 DeepSeek Key 可用。
- **When**：用户询问“北京天气如何”。
- **Then**：回复记录中的 `skill_id=weather`，运行事件包含天气脚本执行，最终回答基于脚本返回的数据而不是声称无工具。

### AC5：兼容原有对话

- **Given**：选中的 Skill 不包含脚本或未选择 Skill。
- **When**：用户发送普通消息。
- **Then**：保持原有单轮文本流行为，现有测试通过。
