## 1. 需求概述

在 `snow-grass` 新建独立 Python/FastAPI 后端，为 `sedum` 提供多模型选择、会话持久化、SSE 流式 Agent 对话、Skill 注册/选择、工具白名单和执行轨迹能力。

## 2. 范围

**In scope（本次做）**：

- FastAPI 工程、环境配置、健康检查和 CORS。
- 基于 Provider Adapter 的多模型目录，预留 DeepSeek/GLM 环境变量。
- SQLite 会话与消息持久化。
- SSE 流式对话和统一 Agent 事件。
- Skill 目录加载、启停、手动/自动选择与工具白名单。
- 不需要真实模型 Key 的自动化测试。

**Out of scope（本次不做）**：

- sedum 前端改造、工作流持久化/运行引擎、Skill 可视化编辑器、用户鉴权和多租户。
- 允许 Skill 执行任意 Python/Shell 代码。
- 真实 DeepSeek/GLM 联调（等待用户提供 Key）。

## 5. API 接口清单

### 健康检查

- **路径**：`/api/v1/health`
- **方法**：`GET`
- **用途**：返回服务状态。
- **数据来源**：本 Spec 定义。

### 模型目录

- **路径**：`/api/v1/models`
- **方法**：`GET`
- **用途**：返回前端可选模型和当前可用性。
- **关键响应字段**：`id`、`name`、`provider`、`available`。
- **数据来源**：`config/models.yaml`。

### Skill 目录与启停

- **路径**：`/api/v1/skills`、`/api/v1/skills/{skill_id}/enable`、`/disable`
- **方法**：`GET`、`POST`
- **用途**：列出、启用和停用 Skill。
- **关键响应字段**：`id`、`name`、`version`、`enabled`、`allowed_tools`。
- **数据来源**：`skills/**/manifest.yaml`。

### 会话与消息

- **路径**：`/api/v1/sessions`、`/api/v1/sessions/{id}/messages`、`/messages/stream`
- **方法**：`GET/POST`
- **用途**：创建/查询会话、查询历史、流式执行 Agent。
- **关键请求参数**：`content`、`model_id`、`skill_id`。
- **关键响应**：SSE `run.started`、`step.started`、`message.delta`、`message.completed`、`run.failed`、`run.completed`。
- **数据来源**：本 Spec 定义。

## 8. 技术实施方案

### 8.1 架构决策

| 决策 | 选择 | 原因 | 放弃的方案 |
|------|------|------|-----------|
| Web 框架 | FastAPI | 异步、类型化、SSE 接入简单 | Django、Flask |
| Agent 编排 | 自研轻量 Runner | 保持事件、Skill 与工具边界可控 | 第一版直接引入 LangChain |
| 多模型 | Provider Adapter + Registry | 业务不依赖具体厂商 SDK | 路由中直接分支调用 |
| 流式协议 | SSE | 符合单向 Token/轨迹输出 | WebSocket |
| 持久化 | SQLAlchemy + SQLite | 本地零运维，后续可切 PostgreSQL | 纯内存、手写 SQL |
| Skill | 文件目录 + manifest | 易版本管理、审查和导入 | 任意动态 Python 代码 |

### 8.2 数据流

```text
src/snow_grass/api/router.py#stream_message
  → persistence/repository.py#add_message
  → skills/registry.py#select
  → agent/runner.py#stream
  → providers/registry.py#resolve
  → providers/openai_compatible.py#stream_chat
  → SSE 事件
  → persistence/repository.py#add_message
```

### 8.3 改动详情

- `core/config.py`：加载 `.env`、数据库/CORS 参数和 YAML 模型目录。
- `providers/*`：定义统一流式协议，Registry 隐藏 Key 并返回可用性。
- `skills/*`：校验 manifest，读取 SKILL.md，支持显式或关键词选择。
- `tools/registry.py`：仅暴露已注册工具，并与 Skill `allowed` 列表取交集。
- `agent/runner.py`：构建 system 指令、输出轨迹并将 Provider 增量转为域事件。
- `api/router.py`：统一异常映射和 SSE 序列化。

### 8.4 状态管理

后端使用应用容器保存无状态 Registry，会话/消息状态写入 SQLite。Skill 启停在 MVP 期间为进程内状态，重启后恢复 manifest 默认值。

### 8.5 异常处理

| 场景 | 处理方式 | 涉及文件 |
|------|---------|---------|
| 模型 Key 缺失 | `/models` 返回 `available=false`，运行时返回 SSE `run.failed` | `providers/registry.py`、`api/router.py` |
| 会话不存在 | HTTP 404 | `api/router.py` |
| Skill 不存在/已停用 | HTTP 400 或 SSE 失败事件 | `skills/registry.py`、`agent/runner.py` |
| Provider 请求失败 | 日志记录脱敏错误，SSE 返回通用错误 | `providers/openai_compatible.py` |
| 客户端断开 | StreamingResponse 取消生成器 | `api/router.py` |

## 9. 验收标准（AC）

### AC1：服务启动

- **Given**：未配置任何模型 Key。
- **When**：启动 FastAPI 并请求 `/api/v1/health`。
- **Then**：数据库表自动创建，接口返回 200 和 `{"status":"ok"}`。

### AC2：模型选择

- **Given**：模型 YAML 包含 DeepSeek 和 GLM。
- **When**：请求 `/api/v1/models`。
- **Then**：返回两类模型，且未配置 Key 时 `available=false`。

### AC3：Skill 管理

- **Given**：内置需求分析 Skill 存在。
- **When**：查询、停用再启用 Skill。
- **Then**：列表状态即时更新，自动选择不会命中已停用 Skill。

### AC4：会话持久化

- **Given**：服务正常。
- **When**：创建会话并写入用户/助手消息。
- **Then**：会话列表和历史接口按时间返回真实数据。

### AC5：流式 Agent

- **Given**：注入一个测试 Provider。
- **When**：调用消息流式接口。
- **Then**：按顺序收到 `run.started`、Skill 轨迹、`message.delta`、`message.completed`和 `run.completed`，完整助手消息被持久化。
