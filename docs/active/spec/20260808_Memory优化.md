## 1. 需求概述

在 Snow Grass 现有“每次向模型发送会话全部历史”的基础上，引入工作记忆、滚动会话摘要、长期记忆和逻辑冷热分层，在保留完整会话原文的同时限制模型上下文大小、降低输入 Token 成本，并为未来 PostgreSQL/pgvector、Redis 和 S3 物理分层预留稳定接口。

## 2. 范围

**In scope（本次做）**：

- 上下文预算：只把受预算约束的 System Prompt、会话摘要、相关长期记忆和最近消息发送给模型。
- 热数据：当前会话最近消息、当前摘要、当前检索结果，直接参与模型推理。
- 冷数据：完整历史消息继续保存在 SQLite，但被摘要覆盖后默认不进入模型上下文。
- 滚动摘要：历史超过阈值时生成新版本摘要，并记录摘要覆盖边界。
- 长期记忆：支持 `session` 和 `workspace` 两种作用域，保存项目事实、用户偏好、决策、任务和约束。
- 记忆治理：来源追踪、置信度、重要度、状态、过期时间、软删除和敏感信息拒绝写入。
- Memory API：查询会话 Memory 状态，管理长期记忆，手动触发会话压缩。
- 可观测性：记录上下文各组成部分的消息数和估算 Token，保留 provider 返回的真实总用量。
- 自动测试：覆盖上下文裁剪、摘要边界、跨会话隔离、记忆检索、敏感信息过滤和失败降级。

**Out of scope（本次不做）**：

- Redis 热缓存、S3/MinIO 对象归档和 PostgreSQL/pgvector 物理迁移。
- 多用户登录、组织权限和用户级跨项目记忆；当前仅支持单用户本地 workspace。
- 向量 Embedding、语义召回和重排序；本期采用类型过滤、关键词、重要度、时效性评分。
- Sedum 记忆管理 UI；本期仅提供后端 API，现有聊天 UI 无需改造。
- 删除冷数据原文；摘要失败时必须能够回退到原消息。

## 5. API 接口清单

### 查询会话 Memory 状态

- **路径**：`/api/v1/sessions/{session_id}/memory`
- **方法**：`GET`
- **用途**：返回当前摘要版本、覆盖边界、热/冷消息数量及最近一次上下文统计。
- **关键请求参数**：
  - `session_id`（string，必填）：会话 ID。
- **关键响应字段**：
  - `summary`（object/null）：当前摘要和覆盖边界。
  - `hot_message_count`（integer）：默认参与上下文的原始消息数。
  - `cold_message_count`（integer）：已被摘要覆盖、仅保留原文的消息数。
  - `last_context_stats`（object/null）：最近一次上下文组成与估算 Token。
- **数据来源**：本地需求设计。

### 手动压缩会话

- **路径**：`/api/v1/sessions/{session_id}/memory/compact`
- **方法**：`POST`
- **用途**：立即生成滚动摘要；未达到阈值时通过 `force` 决定是否执行。
- **关键请求参数**：
  - `force`（boolean，可选，默认 false）：是否忽略阈值。
- **关键响应字段**：
  - `compacted`（boolean）：是否执行压缩。
  - `summary_version`（integer/null）：新摘要版本。
  - `covered_message_count`（integer）：本次新增覆盖消息数。
- **数据来源**：本地需求设计。

### 查询长期记忆

- **路径**：`/api/v1/memories`
- **方法**：`GET`
- **用途**：按作用域、类型和状态查询长期记忆。
- **关键请求参数**：
  - `scope_type`（string，必填）：`session` 或 `workspace`。
  - `scope_id`（string，必填）：会话 ID 或 workspace ID。
  - `status`（string，可选）：`candidate`、`active`、`rejected`、`deleted`。
- **关键响应字段**：
  - `items`（array）：记忆内容、类型、来源、置信度、重要度和生命周期字段。
- **数据来源**：本地需求设计。

### 创建长期记忆

- **路径**：`/api/v1/memories`
- **方法**：`POST`
- **用途**：创建用户明确指定的记忆；手动创建默认直接为 `active`。
- **关键请求参数**：
  - `scope_type`、`scope_id`、`memory_type`、`content`（必填）。
  - `importance`、`expires_at`（可选）。
- **关键响应字段**：
  - `id`、`status`、`created_at`。
- **数据来源**：本地需求设计。

### 更新长期记忆

- **路径**：`/api/v1/memories/{memory_id}`
- **方法**：`PATCH`
- **用途**：纠正内容、激活候选、拒绝候选或调整过期时间。
- **关键请求参数**：
  - `content`、`status`、`importance`、`expires_at`（均可选）。
- **关键响应字段**：
  - 更新后的完整记忆对象。
- **数据来源**：本地需求设计。

### 删除长期记忆

- **路径**：`/api/v1/memories/{memory_id}`
- **方法**：`DELETE`
- **用途**：软删除记忆，默认不再参与检索，保留来源与审计信息。
- **关键请求参数**：
  - `memory_id`（string，必填）。
- **关键响应字段**：HTTP 204。
- **数据来源**：本地需求设计。

## 8. 技术实施方案

### 8.1 架构决策

| 决策 | 选择 | 原因 | 放弃的方案 |
|------|------|------|-----------|
| 冷热分层 | SQLite 内逻辑分层，原文不删除 | 当前为本地单实例，风险低且摘要失败可回退 | 首期直接上 Redis + S3，部署和一致性成本过高 |
| 上下文裁剪 | 消息条数硬上限 + 保守 Token 估算双限制 | 在缺少 DeepSeek 精确本地 tokenizer 时仍可预先控制上下文 | 只按条数无法控制超长消息；只依赖 provider usage 属于事后统计 |
| 摘要方式 | 滚动摘要并保存不可变版本，单一 current 指针 | 可追溯、可恢复，避免重复总结全部历史 | 覆盖写单条摘要，无法审计和回退 |
| 摘要触发 | 下一次请求构建上下文时同步按需压缩 | 无需不可靠的进程内后台任务，事务边界清晰 | `asyncio.create_task` 在重启时可能丢任务 |
| 长期记忆写入 | 手动记忆直接 active；自动提取先进入 candidate | 避免模型推测污染长期记忆 | 自动提取直接激活，错误事实风险高 |
| 检索 | 关键词 + 类型 + 重要度 + 时效 + 置信度 | SQLite 可直接实现，后续可替换向量召回 | 首期引入 Embedding/向量库增加成本 |
| 数据库演进 | 新表优先，避免修改现有消息列 | `create_all` 可安全创建，减少手写 SQLite ALTER | 本期引入 Alembic 会扩大范围，后续 PostgreSQL 阶段再引入 |
| 故障策略 | Memory 失败降级到最近消息窗口，聊天仍可用 | Memory 是增强能力，不应成为主链路单点故障 | Memory 失败直接阻断聊天影响可用性 |

### 8.2 数据流

```text
src/snow_grass/api/router.py#stream_message
  → ChatRepository.add_message(user)
  → MemoryService.prepare_context
      → SessionSummaryRepository.get_current
      → MemoryService.compact_if_needed
      → MemoryRepository.search_active
      → ContextBuilder.build
  → AgentRunner.stream(ContextBundle)
  → ProviderRegistry.resolve / ModelProvider.stream_chat
  → ChatRepository.add_message(assistant + provider usage)
  → MemoryService.record_context_stats
```

读取层次固定为：

```text
Agent 基础指令
→ 当前模型身份与 Skill
→ workspace/session active 长期记忆
→ 当前会话滚动摘要
→ 摘要边界后的最近原始消息
→ 当前用户消息
```

冷热状态不写入 `chat_messages`：当前摘要的 `covered_until_message_id` 之前为逻辑冷数据，之后为热消息。所有原文仍由现有消息接口完整返回。

### 8.4 状态管理

后端继续使用 FastAPI `application.state` 管理长生命周期服务，数据库保存所有可恢复状态；禁止依赖进程内状态作为唯一 Memory 来源。摘要版本切换和长期记忆状态变更均在数据库事务中完成。Sedum 本期无新增状态。

### 8.5 异常处理

| 场景 | 处理方式 | 涉及文件 |
|------|---------|---------|
| 摘要模型请求失败 | 记录原因，回退到最近消息窗口，主对话继续 | `memory/service.py`、`api/router.py` |
| 估算后仍超过 provider 限制 | 继续从最旧热消息裁剪；单条过长则头尾截断 | `memory/context_builder.py` |
| Memory 数据为空 | 仅使用最近消息和当前用户消息 | `memory/context_builder.py` |
| 记忆包含敏感信息 | 返回 422 和通用原因码，不保存原文 | `memory/security.py`、`api/router.py` |
| 摘要事务冲突 | 回滚并读取最新 current 版本，必要时降级 | `persistence/repository.py` |
| 记忆过期或已删除 | 查询阶段排除，不进入模型上下文 | `persistence/repository.py` |
| 会话不存在 | 返回 404，与现有消息接口一致 | `api/router.py` |

## 9. 验收标准（AC）

### AC1：上下文不再全量增长

- **Given**：某会话存在 100 条历史消息。
- **When**：用户发送第 101 条消息。
- **Then**：发送给 provider 的原始历史不超过 24 条且估算输入不超过配置预算，当前用户消息必须保留。

### AC2：滚动摘要和冷数据可恢复

- **Given**：会话历史超过压缩阈值。
- **When**：下一次请求准备上下文。
- **Then**：生成递增版本摘要并记录覆盖边界；被覆盖原消息不进入默认模型上下文，但 `/messages` 仍返回完整原文。

### AC3：Memory 故障不阻断聊天

- **Given**：摘要 provider 抛出异常或数据库摘要写入失败。
- **When**：用户继续发送消息。
- **Then**：系统使用最近消息窗口完成主模型请求，并记录 `memory_degraded` 原因。

### AC4：长期记忆作用域隔离

- **Given**：会话 A、会话 B 和 workspace 分别存在 active 记忆。
- **When**：会话 A 构建上下文。
- **Then**：只能召回会话 A 和当前 workspace 的记忆，不召回会话 B 记忆。

### AC5：记忆生命周期治理

- **Given**：存在 candidate、active、expired、deleted 四类记忆。
- **When**：执行 Memory 检索。
- **Then**：仅 active 且未过期、未删除的记忆可进入上下文。

### AC6：敏感信息保护

- **Given**：待写入内容包含 API Key、Bearer Token 或私钥片段。
- **When**：调用创建记忆接口或自动提取流程。
- **Then**：内容不落库，接口返回 422 或候选被拒绝，日志不得包含敏感原文。

### AC7：Context 统计可解释

- **Given**：一次请求使用了摘要、长期记忆和最近消息。
- **When**：请求完成。
- **Then**：ContextRun 记录各部分条数、估算 Token、裁剪数量和降级原因；provider 真实 usage 独立保留。

### AC8：现有能力兼容

- **Given**：Memory 功能关闭或数据库中没有 Memory 数据。
- **When**：执行现有会话创建、流式聊天、历史查询和 Token 汇总测试。
- **Then**：接口契约保持兼容，现有测试继续通过。

## 10. 待确认事项

无。本 Spec 默认采用本地单用户、SQLite 逻辑冷热分层、24 条最近消息、12k 输入上下文预算、4k 输出预留；所有阈值均可通过环境变量调整。
