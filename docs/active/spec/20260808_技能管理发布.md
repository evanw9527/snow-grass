## 1. 需求概述

在 Snow Grass 增加可持久化的 Skill 管理与发布中心，并在 Sedum 增加对应管理页面，使用户能够创建草稿、编辑标准技能包、执行发布前校验、发布不可变版本、启停、查看版本历史和回滚，同时保证正在运行的 Agent 不受发布切换影响。

## 2. 范围

**In scope（本次做）**：

- 内置 Skill 与自建 Skill 统一展示，内置 Skill 内容只读。
- 自建 Skill 的创建、草稿保存、复制和归档。
- 完整文件树编辑：`SKILL.md`、`manifest.yaml`、`agents/openai.yaml` 以及可选 `scripts/`、`references/`、`assets/`、`tests/`。
- Pydantic Schema、模型引用、工具权限、内容完整性、安全规则和选择测试校验。
- 基于 SemVer 的不可变 Release 发布，可选择发布后立即激活。
- 当前激活版本切换和历史版本回滚，旧 Release 永不覆盖。
- Skill 启用/停用持久化，重启后保持。
- 发布后原子替换运行时 Registry；已开始的 Agent Run 继续使用旧 Skill 快照。
- 草稿 Revision 乐观锁、内容 Hash、发布审计和错误追踪。
- Sedum Skill 管理页面，包括列表、编辑器、校验结果和版本发布侧栏。
- 自动化测试覆盖发布状态机、冲突、运行时刷新、回滚和前端构建。

**Out of scope（本次不做）**：

- 公网 Skill 市场、远程仓库同步、付费、评分和第三方分发。
- 直接执行技能包 `scripts/` 中未经服务端 ToolRegistry 审核和注册的任意代码。
- 多用户登录、角色权限、审批流；首期定位为本机单用户管理台。
- 在线协同编辑、评论和多人冲突合并。
- ZIP 导入导出、Git 发布和云端部署。
- 工具本身的创建与注册；Skill 只能从服务端已注册工具中选择。

## 5. API 接口清单

### 查询 Skill 管理目录

- **路径**：`/api/v1/admin/skills`
- **方法**：`GET`
- **用途**：返回内置和自建 Skill 的管理态摘要。
- **关键请求参数**：
  - `query`（string，可选）：按 ID、名称和描述搜索。
  - `source`（string，可选）：`builtin` 或 `managed`。
  - `status`（string，可选）：`draft`、`published`、`archived`。
- **关键响应字段**：
  - `id`、`source`、`name`、`description`。
  - `lifecycle_status`、`enabled`、`draft_revision`。
  - `active_version`、`has_unpublished_changes`、`updated_at`。
- **数据来源**：本地需求设计。

### 创建自建 Skill

- **路径**：`/api/v1/admin/skills`
- **方法**：`POST`
- **用途**：创建 Skill 实体和 Revision 1 草稿。
- **关键请求参数**：
  - `id`（string，必填）：符合 `^[a-z][a-z0-9_-]*$`，且不能与内置 ID 冲突。
  - `name`、`description`（string，必填）。
- **关键响应字段**：完整 Skill Detail 与草稿。
- **数据来源**：本地需求设计。

### 查询 Skill 详情

- **路径**：`/api/v1/admin/skills/{skill_id}`
- **方法**：`GET`
- **用途**：返回来源、草稿、当前激活 Release、校验状态和版本摘要。
- **关键请求参数**：`skill_id`（string，必填）。
- **关键响应字段**：`skill`、`draft`、`active_release`、`validation_report`、`releases`。
- **数据来源**：本地需求设计。

### 保存 Skill 草稿

- **路径**：`/api/v1/admin/skills/{skill_id}/draft`
- **方法**：`PUT`
- **用途**：用完整快照覆盖草稿，并通过 Revision 乐观锁避免并发覆盖。
- **关键请求参数**：
  - `expected_revision`（integer，必填）。
  - `name`、`description`、`instructions`、`selection`、`models`、`tools`、`limits`、`test_cases`。
- **关键响应字段**：`revision`、`content_hash`、`saved_at`、`validation_status=stale`。
- **数据来源**：本地需求设计。

### 校验 Skill 草稿

- **路径**：`/api/v1/admin/skills/{skill_id}/validate`
- **方法**：`POST`
- **用途**：对指定 Revision 执行发布前完整校验。
- **关键请求参数**：`expected_revision`（integer，必填）。
- **关键响应字段**：
  - `valid`、`validated_hash`。
  - `issues[]`：`severity`、`code`、`field`、`message`。
  - `test_results[]`：测试输入、预期与实际选择结果。
- **数据来源**：本地需求设计。

### 发布 Skill Release

- **路径**：`/api/v1/admin/skills/{skill_id}/publish`
- **方法**：`POST`
- **用途**：从已通过校验且未变化的草稿创建不可变 Release。
- **关键请求参数**：
  - `version`（string，必填）：SemVer，且同一 Skill 不可重复。
  - `expected_revision`（integer，必填）。
  - `activate`（boolean，可选，默认 true）。
  - `release_notes`（string，可选）。
- **关键响应字段**：`release_id`、`version`、`checksum`、`published_at`、`active`。
- **数据来源**：本地需求设计。

### 查询版本历史

- **路径**：`/api/v1/admin/skills/{skill_id}/releases`
- **方法**：`GET`
- **用途**：按发布时间倒序返回不可变 Release。
- **关键请求参数**：`skill_id`（string，必填）。
- **关键响应字段**：`id`、`version`、`checksum`、`release_notes`、`published_at`、`active`。
- **数据来源**：本地需求设计。

### 激活或回滚版本

- **路径**：`/api/v1/admin/skills/{skill_id}/releases/{release_id}/activate`
- **方法**：`POST`
- **用途**：原子切换当前运行版本；激活较旧版本即回滚。
- **关键请求参数**：路径参数 `skill_id`、`release_id`。
- **关键响应字段**：`previous_version`、`active_version`、`activated_at`。
- **数据来源**：本地需求设计。

### 启停 Skill

- **路径**：`/api/v1/admin/skills/{skill_id}/enabled`
- **方法**：`PUT`
- **用途**：持久化 Skill 运行开关，内置和自建 Skill 均支持。
- **关键请求参数**：`enabled`（boolean，必填）。
- **关键响应字段**：`id`、`enabled`、`active_version`。
- **数据来源**：本地需求设计；现有 `/skills/{id}/enable|disable` 保留兼容并转调 SkillService。

### 复制 Skill

- **路径**：`/api/v1/admin/skills/{skill_id}/clone`
- **方法**：`POST`
- **用途**：从内置当前内容或自建指定 Release 创建新的自建草稿。
- **关键请求参数**：`new_id`、`new_name`、`release_id`（可选）。
- **关键响应字段**：新 Skill Detail。
- **数据来源**：本地需求设计。

### 归档 Skill

- **路径**：`/api/v1/admin/skills/{skill_id}/archive`
- **方法**：`POST`
- **用途**：停用并归档自建 Skill；Release 与审计保留。
- **关键请求参数**：`expected_revision`（integer，必填）。
- **关键响应字段**：`id`、`lifecycle_status=archived`、`enabled=false`。
- **数据来源**：本地需求设计。

**整体布局**：

- 左栏使用浅灰背景和紧凑列表，中栏白底编辑，右栏显示发布控制与版本历史。

**交互说明**：

- 新建后立即进入 Revision 1 草稿；内置 Skill 编辑器只读，只提供复制和启停。
- 草稿字段变化后显示“未保存”，点击保存或快捷键 `Cmd/Ctrl+S` 持久化；首期不做自动保存，避免无意发布内容。
- 保存成功后校验状态变为“待校验”；任何新修改都会使旧校验结果失效。
- 校验问题按错误/警告分组，点击问题聚焦对应字段；存在错误时发布按钮不可用，警告允许发布。
- 发布弹窗要求填写版本号；默认勾选“发布后立即激活”。
- 回滚需要二次确认，明确显示当前版本和目标版本；回滚只切换指针，不删除新版本。
- 启停立即生效，但已有 Agent Run 使用启动时快照继续完成。
- Revision 冲突时保留本地编辑内容，展示“服务器草稿已更新”，允许重新加载或复制本地内容后重试。

## 8. 技术实施方案

### 8.1 架构决策

| 决策 | 选择 | 原因 | 放弃的方案 |
|------|------|------|-----------|
| 内容来源 | 内置 Skill 保持文件只读；自建 Skill 草稿和 Release 存 SQLite | 保持现有内置包兼容，同时让管理数据具备事务与审计 | 直接修改 `skills/builtin` 文件，无法保证原子性和版本不可变 |
| Release 模型 | 草稿可变、Release 不可变、Skill 保存 active release 指针 | 发布和回滚语义清晰，可审计和恢复 | 在同一行覆盖 Instructions，历史不可追溯 |
| 运行时刷新 | Registry 分离 builtin/managed，并通过完整字典快照原子替换 | 新请求立即见新版本，运行中的请求持有旧对象不受影响 | 原地逐项修改 dict，读取可能看到半更新状态 |
| 并发控制 | 草稿整数 Revision + `expected_revision` 乐观锁 | 单用户也可能多标签页编辑，实现简单且不持有数据库锁 | 最后写入覆盖，容易丢编辑内容 |
| 发布校验 | `validated_hash == current_content_hash` 才允许发布 | 防止校验后又修改内容绕过校验 | 只记录一次 valid 布尔值，无法判断内容是否变化 |
| 版本规则 | SemVer + `(skill_id, version)` 唯一；历史版本允许重新激活 | 符合发布习惯且回滚不创建伪版本 | 自动覆盖相同版本，破坏不可变性 |
| 工具安全 | 只允许引用 ToolRegistry 已注册工具，发布时强校验 | Skill 不能借配置扩展服务端权限 | 接受任意工具名，运行时静默忽略会掩盖配置错误 |
| 删除策略 | 未发布草稿可删除；已有 Release 只能归档 | 避免破坏历史会话和审计引用 | 对已发布 Skill 物理删除 |
| 首期权限 | 管理 API 默认仅 development 启用并建议绑定 localhost | 符合当前本地单用户定位 | 首期引入完整账号与 RBAC 过重；无条件公网开放不安全 |

### 8.2 数据流

**草稿保存与校验**：

```text
Sedum SkillEditor
→ snowGrassApi.saveSkillDraft
→ api/router.py#save_skill_draft
→ SkillService.save_draft(expected_revision)
→ SkillRepository.update_draft
→ revision + 1 / validated_hash 清空

Sedum SkillReleasePanel
→ snowGrassApi.validateSkill
→ SkillService.validate_draft
→ SkillValidator.validate
→ validation_report + validated_hash 持久化
```

**发布与运行时生效**：

```text
SkillReleasePanel#publish
→ POST /admin/skills/{id}/publish
→ SkillService.publish
→ 同一数据库事务创建 immutable SkillReleaseRecord
→ 可选更新 active_release_id
→ 写 SkillAuditRecord
→ SkillService.refresh_registry
→ SkillRegistry.replace_managed_snapshot
→ 后续 AgentRunner.stream 使用新 LoadedSkill
```

**回滚**：

```text
SkillReleasePanel#activateRelease
→ SkillService.activate_release
→ 校验 release 属于 skill
→ 原子更新 active_release_id
→ audit(action=rollback/activate)
→ 原子刷新 Registry
```

### 8.3 改动详情

#### `src/snow_grass/core/config.py`（修改）

- 新增 `skill_admin_enabled`，默认仅 development 为 true；生产环境必须显式开启。
- 新增 `skill_max_instruction_chars=100000`、`skill_max_test_cases=50`。
- 保留现有 `skills_path` 作为内置 Skill 根目录。

#### `src/snow_grass/persistence/models.py`（修改）

- `ManagedSkillRecord`：`id`、名称、描述、生命周期、enabled、active_release_id、创建/更新时间。
- `SkillDraftRecord`：`skill_id`、revision、结构化 manifest JSON、instructions、test_cases、content_hash、validated_hash、validation_report、更新时间。
- `SkillReleaseRecord`：UUID、skill_id、SemVer、完整 manifest/instructions/test_cases 快照、checksum、release_notes、published_at；对 `(skill_id, version)` 建唯一约束。
- `SkillRuntimeStateRecord`：对内置和自建 Skill 统一保存 enabled override。
- `SkillAuditRecord`：action、skill_id、release_id、revision、before/after 摘要、actor=`local-user`、created_at。

#### `src/snow_grass/skills/schema.py`（修改）

- 保持 `SkillManifest`/`LoadedSkill` 作为运行时契约。
- 新增 `SkillDraftContent`，版本号不属于草稿，由 publish 请求提供。
- 新增 `SkillTestCase`、`ValidationIssue`、`SkillValidationReport`、`SkillReleaseSnapshot`。
- 为名称、描述、关键词、instructions、发布说明和测试数量设置上限。

#### `src/snow_grass/skills/registry.py`（修改）

- `load` 只读取并标记 builtin 快照。
- 内部保存 `_builtin_skills`、`_managed_skills`、`_enabled_overrides`，读取时合并成不可变视图。
- 新增 `replace_managed_snapshot` 和 `apply_enabled_overrides`；先完整构造新字典，再一次赋值。
- `select` 在一次调用开始时获取合并快照，后续不受发布切换影响。

### 8.4 状态管理

Sedum 继续使用 React 本地状态，不引入 Redux。`SkillManagementPage` 是服务端状态协调层，子组件只接收数据和回调。草稿状态包含 `serverDraft`、`editorDraft`、`revision`、`saving`、`validating`、`publishing`；`dirty` 通过规范化比较得出。后端数据库是唯一持久化真相源，SkillRegistry 只是可重建的运行时快照。

### 8.5 异常处理

| 场景 | 处理方式 | 涉及文件 |
|------|---------|---------|
| Skill ID 重复或与内置冲突 | 返回 409，保留创建表单 | `skills/service.py`、`SkillManagementPage.jsx` |
| 草稿 Revision 冲突 | 返回 409 + 当前 Revision，前端保留本地内容并提示重载 | `skills/repository.py`、`SkillEditor.jsx` |
| 校验存在 error | 返回结构化报告并禁用发布；warning 不阻断 | `skills/validation.py`、`SkillReleasePanel.jsx` |
| 校验后草稿被修改 | `validated_hash` 失效，发布返回 409/422 并要求重校验 | `skills/service.py` |
| SemVer 重复或非法 | 返回 422，历史 Release 不变 | `skills/service.py` |
| Registry 刷新失败 | 事务回滚或恢复旧指针，返回 500，现有运行时继续可用 | `skills/service.py` |
| 发布时 Agent 正在运行 | 已有 Run 继续旧快照，新 Run 使用新版本 | `skills/registry.py`、`agent/runner.py` |
| 未注册工具被引用 | 校验 error，禁止发布 | `skills/validation.py` |
| 敏感信息出现在 Instructions | 校验 error，不保存到 Release | `skills/validation.py` |
| 后端不可达 | 页面保留当前编辑内容并提供重试 | `SkillManagementPage.jsx` |
| 管理 API 在生产未启用 | 返回 404，避免暴露管理面 | `api/router.py`、`core/config.py` |

## 9. 验收标准（AC）

### AC1：创建和保存草稿

- **Given**：Skill ID 不与内置或自建 Skill 冲突。
- **When**：用户创建 Skill 并保存编辑内容。
- **Then**：数据库产生 Revision 递增的草稿，服务重启后内容仍存在，运行时 Agent 不受未发布草稿影响。

### AC2：Revision 冲突保护

- **Given**：两个页面同时打开 Revision 3 草稿，其中一方已保存为 Revision 4。
- **When**：另一方仍以 expected_revision=3 保存。
- **Then**：接口返回 409 和 current_revision=4，不覆盖服务器草稿，前端保留本地内容。

### AC3：完整发布校验

- **Given**：草稿引用未知模型、未注册工具、空 Instructions 或包含敏感凭据。
- **When**：用户点击校验。
- **Then**：返回字段级 error，`valid=false`，发布按钮不可用且数据库不创建 Release。

### AC4：不可变版本发布

- **Given**：当前 Revision 的 content_hash 与 validated_hash 一致且校验通过。
- **When**：用户发布 `1.0.0`。
- **Then**：创建 checksum 固定的 Release；再次发布相同 Skill/version 返回 422，原 Release 不变化。

### AC5：原子运行时生效

- **Given**：Skill `1.0.0` 已激活且一个 Agent Run 正在执行。
- **When**：发布并激活 `1.1.0`。
- **Then**：正在运行的请求继续使用 `1.0.0` 快照，之后的新请求使用 `1.1.0`，不存在半更新状态。

### AC6：回滚

- **Given**：Skill 存在 `1.0.0` 和当前激活的 `1.1.0`。
- **When**：用户激活历史 `1.0.0`。
- **Then**：active version 原子切换为 `1.0.0`，`1.1.0` 保留，审计记录 action=`rollback`。

### AC7：启停持久化

- **Given**：内置或自建 Skill 当前已启用。
- **When**：用户停用并重启 Snow Grass。
- **Then**：该 Skill 仍为停用状态，自动和显式选择均不可使用。

### AC8：内置 Skill 保护与复制

- **Given**：用户打开内置 `requirement_analysis`。
- **When**：尝试编辑或归档。
- **Then**：界面只读且接口拒绝；用户可以复制为不同 ID 的自建 Revision 1 草稿。

### AC9：管理页面完整交互

- **Given**：Snow Grass 可访问并返回 Skill 目录。
- **When**：用户在 Sedum 完成创建、保存、校验、发布、停用和回滚。
- **Then**：每一步均显示明确状态，刷新页面后与服务器一致，前端 lint/build 通过。

### AC10：兼容现有 Agent

- **Given**：已有会话使用 `/api/v1/skills` 和 Skill 自动选择。
- **When**：升级到新版本但未创建任何自建 Skill。
- **Then**：内置 Skill 列表、选择逻辑、流式对话和现有测试行为保持兼容。

### AC11：审计可追溯

- **Given**：对某 Skill 执行保存、校验、发布、回滚和停用。
- **When**：查询其审计记录。
- **Then**：按时间倒序返回动作、Revision、Release、结果和 actor，且不记录完整 Instructions 或敏感内容。

## 10. 待确认事项

无。本 Spec 默认定位本机单用户环境，管理 API 仅在 development 开启；Skill 发布目标是 Snow Grass 本地运行时，不包含公网市场或 Git/云端分发。
