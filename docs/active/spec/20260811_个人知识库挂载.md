## 1. 需求概述

在 Snow Grass 中建立工作区级个人知识库，自动索引 FatPet 上传的本地输入和 DeepSeek 生成的小时总结，在用户与 FatPet 或 Sedum Agent 对话时检索相关记录并以可追溯、非指令的上下文挂载。

## 2. 范围

**In scope（本次做）**：

- 为本地输入和小时总结建立统一的知识文档模型、来源标识、去重与删除联动。
- 在 SQLite 使用 FTS5 trigram 全文索引，按文本相关性、来源质量和时间新鲜度排序；FTS5 不可用时退化到参数化 `contains` 检索。
- 知识检索自动接入现有 `MemoryService.prepare_context` 链路，FatPet 和 Sedum Agent 共享同一份检索结果。
- 提供“服务端总开关 + 会话持久开关 + 单次请求覆盖”三层控制，关闭后不检索、不向模型注入知识。
- 提供检索、列表、重建索引和按文档删除 API，返回来源与时间以便追溯。
- 在 Sedum 将两类来源展示为两个知识库，知识库级支持启用/停用；条目级支持搜索、追溯、单条/批量删除和重建索引。
- 增加开关、检索条数、上下文 Token 上限、保留期等配置。
- 补齐后端自动化测试，覆盖入库、更新、检索、注入、删除和降级。

**Out of scope（本次不做）**：

- 不引入外部向量数据库、Embedding 供应商或云端知识库。
- 不支持直接编辑由本地输入/小时总结派生的知识正文；管理页只管理可检索状态和生命周期，避免与来源失同。
- 不将聊天消息全量自动写入本知识库；现有会话 Memory 仍独立运行。
- 不做跨设备同步、多用户权限或知识共享。

## 5. API 接口清单

### 检索知识

- **路径**：`/api/v1/knowledge/search`
- **方法**：`POST`
- **用途**：供调试、后续 UI 和内部服务使用同一检索语义。
- **关键请求参数**：
  - `query`（string，必填，1–200 字符）：查询文本。
  - `limit`（integer，可选，默认 8，1–20）：返回上限。
  - `source_types`（array[string]，可选）：`activity_event` / `hourly_summary`。
  - `start` / `end`（ISO-8601 datetime，可选）：来源时间范围。
- **关键响应字段**：
  - `items[].id/content/title/source_type/source_id/source_app/occurred_at/score`。
  - `degraded_reason`（string|null）：检索降级原因。
- **数据来源**：基于现有 FastAPI 路由风格设计，无外部 API。

### 分页列出知识文档

- **路径**：`/api/v1/knowledge/documents`
- **方法**：`GET`
- **用途**：查看已入库文档及来源。
- **关键请求参数**：`page`、`page_size`、`query`、`source_type`、`status`、`start`、`end`。
- **关键响应字段**：`items`、`total`、`page`、`page_size`。
- **数据来源**：本地 Snow Grass SQLite。

### 重建知识索引

- **路径**：`/api/v1/knowledge/reindex`
- **方法**：`POST`
- **用途**：幂等回填历史活动和小时总结。
- **关键请求参数**：`source_types`（可选）、`start`（可选）、`restore_deleted`（boolean，可选，默认 `false`）。
- **关键响应字段**：`indexed`、`updated`、`skipped`、`failed`。
- **数据来源**：现有 `activity_events` 与 `hourly_activity_summaries`表。

### 删除知识文档

- **路径**：`/api/v1/knowledge/documents/{document_id}`
- **方法**：`DELETE`
- **用途**：将单条知识软删除为 tombstone 并从全文索引移除，不反向删除原始活动。
- **关键请求参数**：`document_id`（path string，必填）。
- **关键响应字段**：HTTP `204 No Content`。
- **数据来源**：本地 Snow Grass SQLite。

### 创建会话时设置知识开关

- **路径**：`/api/v1/sessions`
- **方法**：`POST`
- **用途**：创建 FatPet/Sedum 会话时设置持久的知识挂载策略。
- **关键请求参数**：`knowledge_enabled`（boolean，可选，默认 `false`）。
- **关键响应字段**：`knowledge_enabled`（boolean）。
- **数据来源**：扩展现有会话 API。

### 更新会话知识开关

- **路径**：`/api/v1/sessions/{session_id}/knowledge`
- **方法**：`PATCH`
- **用途**：切换当前会话后续是否挂载知识。
- **关键请求参数**：`enabled`（boolean，必填）。
- **关键响应字段**：更新后的 `SessionResponse`。
- **数据来源**：本地 `chat_sessions`。

### 单次消息覆盖

- **路径**：`/api/v1/sessions/{session_id}/messages/stream`
- **方法**：`POST`
- **用途**：FatPet 以当前本地隐私开关立即控制本次对话。
- **关键请求参数**：`knowledge_enabled`（boolean|null，可选）；有值时覆盖会话设置，无值时继承会话设置。
- **关键响应字段**：现有 SSE 协议不变；`run.started.context_stats` 可检查实际挂载数。
- **数据来源**：扩展现有流式消息 API。

### 知识库状态总览

- **路径**：`/api/v1/knowledge/stats`
- **方法**：`GET`
- **用途**：管理页展示能力是否可用、索引模式与各状态/来源数量。
- **关键响应字段**：`globally_enabled`、`index_mode`（`fts5_trigram` / `contains_fallback`）、`total`、`active`、`disabled`、`deleted`、`activity_events`、`hourly_summaries`、`last_indexed_at`。
- **数据来源**：`knowledge_documents` 与运行时 FTS 能力检测。

### 更新知识库状态

- **路径**：`/api/v1/knowledge/bases/{source_type}`
- **方法**：`PATCH`
- **用途**：启用或停用整个来源知识库；停用时继续同步数据，但不参与检索。
- **关键请求参数**：`enabled`（boolean，必填）。
- **关键响应字段**：知识库名称、来源类型、启用状态、条目数量与最近更新时间。
- **数据来源**：本地 Snow Grass SQLite。

### 批量管理知识

- **路径**：`/api/v1/knowledge/documents/batch`
- **方法**：`POST`
- **用途**：对勾选的具体知识条目批量软删除。
- **关键请求参数**：`document_ids`（array[string]，1–100）、`action=delete`。
- **关键响应字段**：`matched`、`updated`、`skipped`。
- **数据来源**：本地 Snow Grass SQLite。

## 8. 技术实施方案

### 8.1 架构决策

| 决策 | 选择 | 原因 | 放弃的方案 |
|------|------|------|-----------|
| 知识库归属 | Snow Grass 工作区级单一数据源 | FatPet 和 Sedum 都已依赖 Snow Grass，可避免两份索引漂移 | FatPet 本地单独建库；客户端和服务端各存一份 |
| 文档模型 | 独立 `knowledge_documents` 并保留来源 | 原始活动、小时总结与会话 Memory 生命周期不同 | 全部塞入 `memory_items`，会丢失来源语义并混淆用户确认记忆 |
| 检索引擎 | SQLite FTS5 trigram + 参数化查询降级 | 不增加服务依赖，对中文子串召回较稳定，支持本地部署 | 云向量库；仅 SQL `LIKE`；第一期引入 Embedding |
| 排序 | BM25 + 来源权重 + 时间衰减 | 小时总结信息密度更高，同时保留原始证据的召回能力 | 纯时间排序；纯 BM25；每次先请求 DeepSeek 重写查询 |
| 挂载位置 | `MemoryService.prepare_context` 统一检索 | 通用 Agent 与 FatPet 对话均已走该链路，可保证策略一致 | 在 Swift 端先搜再传；在 `AgentRunner` 内耦合数据库 |
| 使用控制 | 全局 AND（请求覆盖 ?? 会话开关） | 后端可一键熄断，用户又能按会话或当次消息选择；关闭默认更符合隐私预期 | 只有服务端环境变量；只在前端隐藏但后端仍检索 |
| 上下文安全 | XML 边界 + 明确“证据非指令” + Token 独立预算 | 本地输入可能包含 prompt injection 文本，不能当系统指令解释 | 原文直接拼入 system prompt；无上限全量挂载 |
| 失败策略 | 知识能力 fail-open | 索引不应阻塞活动采集和对话主链路 | 索引失败使上传/对话整体失败 |
| 管理删除 | 软删除 tombstone，检索排除 | 保留“用户不希望再出现”的决定，防止 reindex 从来源再次写回 | 物理删除知识行；同时删除原始活动 |

### 8.2 数据流

```text
FatPet/TextActivityCaptureService
  → FatPet/ActivitySyncService.enqueue + flush
  → POST /api/v1/activity-events/batch
  → ActivityService.ingest
  → ActivityRepository.insert_batch
  → KnowledgeService.index_activity_events
  → knowledge_documents + knowledge_documents_fts

FatPet/ActivityIntelligenceService.createHourlySummary
  → POST /api/v1/activity-events/hourly-summary
  → ActivityService.hourly_summary
  → ActivityIntelligence.summarize + ActivityRepository.save_hourly_summary
  → KnowledgeService.index_hourly_summary
  → knowledge_documents + knowledge_documents_fts

FatPet/PetConversationStore.send 或 Sedum Agent 发送消息
  → POST /api/v1/sessions/{session_id}/messages/stream
  → effective_enabled = global_enabled AND (request_override ?? session.knowledge_enabled)
  → effective_enabled=false：跳过知识检索
  → MemoryService.prepare_context
  → KnowledgeService.search(最新 user message)
  → ContextBuilder.build(<retrieved_knowledge>)
  → AgentRunner.stream
  → DeepSeek/GLM Provider
```

### 8.3 改动详情

#### `src/snow_grass/knowledge/models.py`（新增）

- `KnowledgeDocumentRecord`：字段包含 `id/workspace_id/source_type/source_id/title/content/keywords_json/source_app/occurred_at/content_hash/status/created_at/updated_at`。
- 建立 `(workspace_id, source_type, source_id)` 唯一约束，使活动重传、总结重算和 reindex 均幂等。

#### `src/snow_grass/knowledge/repository.py`（新增）

- `upsert_documents`：根据来源键批量 upsert，`content_hash` 未变时跳过。
- `search`：优先通过 FTS5 trigram + `bm25()` 候选召回，再在 Python 中加入来源和时间分。
- `fallback_search`：在 FTS5 未编译、虚表损坏或查询语法异常时使用 SQLAlchemy `contains(autoescape=True)`。
- `delete_by_sources/delete_document/purge_before`：同步清理主表和 FTS 行。
- `list_bases/set_base_enabled`：提供两个知识库的统计与启停策略；`batch_action` 负责条目软删除，`deleted` 行保留为 tombstone。

#### `src/snow_grass/knowledge/service.py`（新增）

- `index_activity_events`：将清洗后的活动文本映射为 `activity_event` 文档，标题使用应用名与时间。
- `index_hourly_summary`：按“已完成/进行中/阻塞/下一步”序列化成稳定文本，保留结构标签供检索。
- `search`：空白查询直接返回空；去除重复内容；默认 summary 权重 1.25、raw 权重 1.0；返回前按最终 score 降序。
- `reindex`：分页读取两类来源并幂等 upsert，单条失败记数但不中断整批。
- 检索先过滤已停用的知识库，再过滤已删除条目；普通 upsert/reindex 尊重 tombstone，不自动恢复已删除知识。

- 导入 knowledge models 注册元数据。

### 8.4 状态管理

后端以 SQLite `knowledge_documents` 作为知识持久状态，FTS 虚表为可重建的派生状态，`chat_sessions.knowledge_enabled` 作为会话挂载状态。FatPet 使用 UserDefaults 保存用户级偏好并通过每次请求覆盖；Sedum 的 `AgentPage` 镜像会话开关，`KnowledgeManagementPage` 使用页内 React state 管理筛选、勾选、分页和展开详情，服务端仍是状态真源。

### 8.5 异常处理

| 场景 | 处理方式 | 涉及文件 |
|------|---------|---------|
| FTS5/trigram 不可用 | 记录降级原因，改用参数化 contains 检索 | `knowledge/repository.py`、`persistence/database.py` |
| 知识入库失败 | 不回滚已成功的活动/总结；后续可 reindex 修复 | `activity/service.py`、`knowledge/service.py` |
| 检索超时 | 返回空知识上下文，对话继续 | `memory/service.py` |
| 查询为空/无命中 | 不注入 `<retrieved_knowledge>` | `knowledge/service.py`、`memory/context_builder.py` |
| 来源重复上传 | 唯一键 + content hash 跳过重复索引 | `knowledge/models.py`、`knowledge/repository.py` |
| 来源被删除 | 同一业务操作联动删除索引副本；失败时 reindex 再对账 | `activity/service.py`、`knowledge/service.py` |
| 文本含 prompt injection | 检索内容按不可信证据包裹，不改写 system instructions | `memory/context_builder.py` |
| 开关更新失败 | Sedum UI 回滚到服务端旧值；FatPet 本次请求按本地开关显式传值 | `AgentPage.jsx`、`SnowGrassClient.swift` |
| 全局总开关关闭 | 忽略会话/请求的 true，不执行检索，统计中标记 `knowledge_globally_disabled` | `api/router.py`、`memory/service.py` |
| 管理操作部分失败 | 批量响应返回 matched/updated/skipped，页面刷新真实状态并显示结果 | `knowledge/router.py`、`KnowledgeManagementPage.jsx` |
| 重建索引时有 tombstone | 默认保留 deleted；仅显式恢复模式才清除 tombstone | `knowledge/service.py`、`KnowledgeManagementPage.jsx` |

## 9. 验收标准（AC）

### AC1：本地输入自动入库

- **Given**：FatPet 上传一批包含两条新活动和一条重复活动的数据。
- **When**：`POST /api/v1/activity-events/batch` 返回成功。
- **Then**：知识库仅新增两条 `activity_event` 文档，内容是脱敏后文本，每条可追溯到 `client_event_id`。

### AC2：DeepSeek 总结入库

- **Given**：一个小时内有足够活动且 DeepSeek 返回合法结构。
- **When**：生成小时总结。
- **Then**：产生唯一 `hourly_summary` 文档，包含标题、关键词和四类总结内容；对同一小时重试不产生重复文档。

### AC3：中文检索与排序

- **Given**：库中同时存在与“登录失败”相关的原始输入和小时总结。
- **When**：检索“登录问题怎么处理”。
- **Then**：返回不超过 `limit` 条结果，每条含来源和 score，精确命中且较新的小时总结排在弱相关旧输入前。

### AC4：Agent 挂载

- **Given**：会话最新用户问题命中两条知识。
- **When**：`MemoryService.prepare_context` 构建上下文。
- **Then**：`ContextBundle.system_memory` 包含两条带 `[K1]/[K2]` 来源标记的 `<retrieved_knowledge>`，且总 Token 不超过配置预算。

### AC5：FatPet 无感生效

- **Given**：FatPet 使用现有 `PetConversationStore.send` 发起 Agent 流式会话，未升级客户端请求协议。
- **When**：用户询问历史工作内容。
- **Then**：Snow Grass 在保持现有 SSE 事件结构的情况下完成知识检索与回答。

### AC6：删除与保留期

- **Given**：原始活动已有对应知识文档。
- **When**：该活动被单条删除、范围删除或因 `activity_retention_days` 过期。
- **Then**：对应 raw 知识和 FTS 索引行同步消失，后续检索不再返回该内容。

### AC7：降级不阻断主链路

- **Given**：FTS5 不可用或知识检索报错。
- **When**：FatPet 上传活动或用户发起对话。
- **Then**：活动仍正常持久化，对话仍正常返回，`context_stats` 记录降级原因。

### AC8：历史数据回填

- **Given**：现有数据库已有本地输入和小时总结，知识表为空。
- **When**：连续两次调用 reindex。
- **Then**：第一次完成回填，第二次不新增重复文档，搜索结果一致。

### AC9：挂载开关可控

- **Given**：当前问题能命中知识库，但会话开关为关闭。
- **When**：用户发送消息且未提供单次覆盖。
- **Then**：不调用知识检索，`knowledge_count=0`，提供给模型的上下文不含 `<retrieved_knowledge>`。

### AC10：FatPet 切换立即生效

- **Given**：FatPet 已建立会话，知识开关由关闭切换为打开。
- **When**：用户发送下一条消息。
- **Then**：该消息请求携带 `knowledge_enabled=true`，无需重建会话即执行检索；再次关闭后下一条消息不检索。

### AC11：总开关优先

- **Given**：服务端 `knowledge_enabled=false`，会话或单次请求为 `true`。
- **When**：用户发送消息。
- **Then**：知识检索仍被跳过，且对话主链路正常返回。

### AC12：知识管理台账

- **Given**：知识库包含两种来源和 active/disabled/deleted 文档。
- **When**：用户打开 Sedum“知识库”并按关键词、来源和状态筛选。
- **Then**：总览数字来自真实 stats API，台账只展示匹配文档，每条可查看来源 ID、应用和发生时间。

### AC13：知识库启停与条目删除

- **Given**：本地活动输入知识库包含 3 条有效知识。
- **When**：用户停用该知识库，并对其中 1 条知识确认删除。
- **Then**：该来源整体不参与 Agent 检索；1 条知识成为 deleted tombstone，其余知识在重新启用知识库后可恢复检索，原始活动仍保留。

### AC14：重建不恢复已删除知识

- **Given**：某来源文档已在管理页删除，但原始活动仍存在。
- **When**：用户执行普通“重建索引”。
- **Then**：该文档仍为 deleted 且不参与检索；只有使用 `restore_deleted=true` 的明确恢复操作才能重新激活。
