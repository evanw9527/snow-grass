## 1. 需求概述

采集 DeepSeek/GLM 流式响应中的真实 Token usage，按助手消息持久化，提供近 30 天汇总与模型拆分 API，并在 Sedum 侧边栏“最近对话”上方显示。

## 2. 范围

**In scope（本次做）**：

- Provider 请求 `stream_options.include_usage=true`。
- 传递 input/output/total tokens 至 Agent 完成事件。
- 消息表增加 Token 字段，兼容现有 SQLite 数据库自动补列。
- `GET /api/v1/usage/summary?days=30` 聚合总量、输入、输出、调用次数、会话数和模型拆分。
- Sedum 初始加载和每次 Agent 完成后刷新用量卡片。

**Out of scope（本次不做）**：

- Token 价格/金额估算、日趋势图、历史无 usage 消息的估算回填。

## 5. API 接口清单

### Token 用量汇总

- **路径**：`/api/v1/usage/summary`
- **方法**：`GET`
- **请求参数**：`days`（int，1-365，默认 30）
- **响应字段**：`period_days`、`input_tokens`、`output_tokens`、`total_tokens`、`requests`、`sessions`、`by_model[]`
- **数据来源**：Snow Grass SQLite 中 role=assistant 的真实 usage。

## 8. 技术实施方案

### 8.1 架构决策

| 决策 | 选择 | 原因 | 放弃的方案 |
|------|------|------|-----------|
| Usage 来源 | 厂商 API 最终 chunk | 真实、可对账 | 按字符数估算 |
| 存储粒度 | 每条 assistant message | 可按模型/会话聚合 | 只存全局累计值 |
| 历史兼容 | 启动时 SQLite 补列 | 当前 MVP 无 Alembic 基线 | 删库重建 |
| 前端刷新 | 启动 + 每次运行 finally | 实时且无轮询 | 定时轮询 |

### 8.2 数据流

```text
DeepSeek usage chunk
  → OpenAICompatibleProvider
  → AgentRunner message.completed.usage
  → ChatRepository.add_message
  → ChatRepository.usage_summary
  → GET /api/v1/usage/summary
  → AgentPage
  → ChatSidebar UsageSummaryCard
```

### 8.3 改动详情

- Provider 将文本 delta 与 TokenUsage 封装为统一 `ModelStreamChunk`。
- Repository 只统计助手消息，requests 只计入 `total_tokens > 0` 的真实用量记录。
- UI 在消息流完成/失败后都尝试刷新，刷新失败不影响对话。

### 8.4 状态管理

`AgentPage` 增加 `usageSummary` state，不引入全局 Store。

### 8.5 异常处理

| 场景 | 处理方式 | 涉及文件 |
|------|---------|---------|
| Provider 不返回 usage | Token 字段为 0，不计入 requests | `runner.py`、`repository.py` |
| 旧数据库缺列 | 启动事务中自动 ALTER TABLE | `database.py` |
| 用量 API 失败 | 卡片显示 0，不阻塞聊天 | `AgentPage.jsx` |

## 9. 验收标准（AC）

### AC1：真实 Usage 采集

- **Given**：Provider 返回 prompt/completion/total usage。
- **When**：Agent 流式完成。
- **Then**：`message.completed` 包含用量且助手消息持久化相同数值。

### AC2：旧库迁移

- **Given**：现有 `chat_messages` 无 Token 列。
- **When**：启动新版服务。
- **Then**：保留原数据并增加 3 个默认 0 的列。

### AC3：用量聚合

- **Given**：存在多条带 usage 的助手消息。
- **When**：请求 `/usage/summary?days=30`。
- **Then**：总量、输入、输出、请求数、会话数和模型拆分准确。

### AC4：侧边栏展示

- **Given**：Sedum 已连接 Snow Grass。
- **When**：页面加载或 Agent 完成回答。
- **Then**：对话列表上方显示最新近 30 天 Token 数据。

### AC5：质量检查

- **Given**：代码完成。
- **When**：运行后端 ruff/mypy/pytest 与前端 lint/build。
- **Then**：全部通过。
