## 1. 需求概述

在 Snow Grass 的 Skill Python 脚本执行链路增加结构化结果缓存，并在 Sedum 执行轨迹中明确展示缓存命中、实际执行和强制刷新。

## 2. 范围

**In scope（本次做）**：
- 基于 Skill 版本、脚本路径和标准化参数生成缓存键。
- 支持 workspace/session/run 作用域、成功 TTL、失败短 TTL 和强制刷新。
- 天气 Skill 默认配置 10 分钟 workspace 缓存。
- SSE 返回缓存状态、缓存时间、过期时间和命中次数。
- Sedum 时间线展示复用结果与缓存详情。

**Out of scope（本次不做）**：
- 不解析历史助手回答来反向生成缓存。
- 不实现 Redis、跨进程分布式锁和缓存管理页面。
- 不缓存模型最终自然语言回答。

## 3. 功能要点

## 8. 技术实施方案

### 8.1 架构决策

| 决策 | 选择 | 原因 | 放弃的方案 |
|------|------|------|-----------|
| 缓存判断位置 | 模型发起工具调用后、脚本执行前 | 保留工具调用语义，判断确定且可测试 | 让模型从上下文自行判断 |
| 缓存内容 | 原始 `SkillScriptResult` | 可根据新问题重新生成回答 | 缓存最终回答文本 |
| 持久化 | 现有 SQLAlchemy 数据库 | 与 SQLite/后续数据库统一 | 仅内存缓存、Redis |
| 版本隔离 | 缓存键包含 Skill 版本 | 新发布自动失效 | 发布时批量删除 |
| 刷新判断 | 后端识别显式刷新词并覆盖模型策略 | 用户意图不可被模型忽略 | 仅信任模型参数 |

### 8.2 数据流

```text
api/router.py#stream_message
→ agent/runner.py#stream
→ tools/result_cache.py#resolve
→ skills/executor.py#execute（仅 miss/refresh）
→ tools/result_cache.py#save
→ AgentEvent(step.completed)
→ sedum AgentPage.jsx
→ MessageTimeline.jsx
```

### 8.3 改动详情

#### `src/snow_grass/tools/result_cache.py`（新增）
- 生成稳定 SHA-256 缓存键，参数采用规范 JSON。
- 查询有效记录、区分 miss/expired/refresh/disabled，并保存成功或短期失败结果。

#### `src/snow_grass/agent/runner.py`（修改）
- 从当前用户消息识别强制刷新语义。
- 对每次脚本调用先查询缓存，命中时不创建 Python 子进程。
- 将缓存元数据加入脚本完成事件。

#### Sedum 时间线（修改）
- 用 SSE 元数据形成可读摘要和展开详情，不额外请求缓存接口。

### 8.4 状态管理

后端缓存状态持久化在数据库；前端继续使用 `AgentPage` 本地消息状态，不新增全局 Store。

### 8.5 异常处理

| 场景 | 处理方式 | 涉及文件 |
|------|---------|---------|
| 缓存读写失败 | 降级为实际执行，不影响主流程 | `tools/result_cache.py`、`runner.py` |
| 缓存过期 | 标记 expired 并重新执行覆盖 | `tools/result_cache.py` |
| 脚本失败 | 按 error TTL 短期缓存 | `tools/result_cache.py` |
| 用户强制刷新 | 忽略有效缓存并重新执行 | `runner.py` |

## 9. 验收标准（AC）

### AC1：相同查询复用
- **Given**：天气 Skill 10 分钟缓存已启用且北京查询成功。
- **When**：10 分钟内再次以等价参数查询北京。
- **Then**：不执行子进程，返回相同原始结果，事件为 `cache_status=hit`。

### AC2：参数与版本隔离
- **Given**：存在北京天气缓存。
- **When**：查询上海或发布新 Skill 版本后查询北京。
- **Then**：缓存未命中并实际执行脚本。

### AC3：强制刷新
- **Given**：存在有效北京天气缓存。
- **When**：用户要求“重新查询北京最新天气”。
- **Then**：绕过缓存、实际执行并更新缓存，事件为 `cache_status=refresh`。

### AC4：前端可观测
- **Given**：后端返回 hit 或 refresh 事件。
- **When**：Sedum 渲染执行轨迹。
- **Then**：折叠摘要和展开详情均能区分复用与执行。
